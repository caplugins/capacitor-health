# Supported types

0.1.0 covers **142 types**: reproductive health, activity, vitals and body measurements. Each has
one camelCase id on both platforms. `getSupportedTypes()` tells you what the running device actually
supports (OS version, Health Connect features), with values and units.

How to read the table:

- **Kind**: `quantity` (a number with a unit), `category` (one value from a set), `event` (no
  value, only a time range) or `special` (its own shape: periods, blood pressure, skin temperature).
- **HealthKit**: the identifier without its `HK…TypeIdentifier` prefix, the first iOS version that
  has it, and whether apps can write it. **Combined** ids read several HealthKit types (see below).
- **Health Connect**: the record class and its read / write permission, without the
  `android.permission.health.` prefix. Declare the permissions you use in your app's manifest
  ([Android setup](setup-android.md)).
- `—` means the platform has no such type: it reports `supported: false` with
  `reason: 'notOnPlatform'`, and calls with it reject with `UNSUPPORTED_TYPE`.
- **Values or units**: category values (platform-only ones marked) or quantity units, canonical
  first.

## Type notes

### Combined ids

`distance`, `speed` and `power` are one record on Health Connect but several types on HealthKit
(walking and running distance, cycling distance, swimming distance, …). On iOS a combined id:

- **reads** every member type; each sample keeps the combined id as its `type` and names its
  HealthKit type in `native.type`;
- **writes** to its first member (`distanceWalkingRunning`, `walkingSpeed`, `runningPower`). Write a
  member id (`distanceCycling`) to choose another;
- **aggregates** by summing its members (`distance`); `speed` and `power` give `min` and `max` but no
  `avg`.

### Aggregate-only types

`totalEnergy` on iOS and `basalEnergy` on Android exist only as aggregates on that platform.
`getSupportedTypes()` reports them `readable: false` with `reason: 'aggregateOnly'`;
`readSamples()` and `getChanges()` reject them with `UNSUPPORTED_TYPE`; `aggregate()` works.

### Read-only types

Types Apple computes itself (`wristTemperature`, `exerciseTime`, the heart-rate and audio
notifications, the cycle-deviation notifications, …) can be read but not written: `writable: false`
with `reason: 'readOnly'`, and writes reject with `READ_ONLY_TYPE`.

### Blood pressure

- A `bloodPressure` sample carries `systolic` and `diastolic` in mmHg, plus `bodyPosition`
  (`standingUp`, `sittingDown`, `lyingDown`, `reclining`) and `measurementLocation` (`leftWrist`,
  `rightWrist`, `leftUpperArm`, `rightUpperArm`) on Android. Apple Health and Health Connect both
  show it as one reading.
- On iOS it's a correlation of a systolic and a diastolic sample. The plugin asks for access to
  those two types, which HealthKit's sheet shows as "Blood Pressure". Readings another app saved as
  loose systolic / diastolic samples, without the correlation, aren't returned.
- On Android it's a single moment (`endDate` equal to `startDate` or absent) and Health Connect's
  ranges apply: systolic 20–200, diastolic 10–180.

### Skin temperature (Android)

`skinTemperature` is a `SkinTemperatureRecord`: an optional `baseline` plus `deltas`
(`{ time, delta }`), each the difference from the baseline, with times inside the sample's range.
It needs Health Connect's skin temperature feature, available on Android 14 and later.

### Typed fields

Some types carry extra fields: `measurementLocation` (body, basal and skin temperature),
`relationToMeal`, `mealType`, `specimenSource` (`bloodGlucose`), `testType` / `measurementMethod`
(`vo2Max`) and `reason` (`insulinDelivery`, required on iOS). See
[Reading and writing → The sample shape](reading-and-writing.md#the-sample-shape) and the
[API reference](api.md).

## Passthrough ids (`hk:…`)

For a HealthKit type the plugin has no unified id for yet, pass `hk:` plus its identifier as the
`type`: `hk:HKQuantityTypeIdentifierDietaryWater`, `hk:HKCategoryTypeIdentifierSleepAnalysis`.

- iOS reads, writes, deletes, follows (`getChanges`) and authorizes them. `getSupportedTypes()`
  doesn't list them and `aggregate()` doesn't take them.
- Values stay native: quantities in `unit` (required when writing, one of the plugin's unit ids that
  fits the type; reads default to the first that fits), categories as HealthKit's raw integers.
- The plugin knows which values HealthKit accepts for each category and rejects others (HealthKit
  would crash the app on them). The iOS 16 sleep stages are left out on iOS 15. Identifiers newer
  than the plugin can only be read.
- A type that has a unified id rejects with `INVALID_ARGUMENT`, `data.reason: 'registeredType'` and
  `data.type` naming the id to use. When a later version registers a type, switch to its id.
- `hc:` ids are reserved. Every record of the Health Connect library the plugin uses already has a
  unified id, so they reject with `UNSUPPORTED_TYPE`.
- On Android, `hk:` ids reject with `UNSUPPORTED_TYPE`.
